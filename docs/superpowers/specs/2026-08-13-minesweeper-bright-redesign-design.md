# 扫雷：明亮竞技科技风整体重构设计

## 目标

把当前近黑、低对比、模块拼贴感较强的界面，重构为健康、明亮、年轻且具有竞技张力的桌面扫雷。项目名称始终为“扫雷”；赛博朋克仅作为边缘高光、科技纹理和状态反馈的视觉语言，不出现在产品名称中。

本次重构覆盖登录、注册、语言选择、大厅、个人档案、排行榜、游戏 HUD、棋盘、结算和发布包。账号、本地数据库、联网排行榜及其数据契约不属于视觉重构范围，不得破坏或重建。

## 设计方向

采用“日夜混合竞技风”：以清透的中深蓝建立空间和恢宏感，以银蓝和冰灰面板提高整体明度，再用青蓝、薄荷绿、明黄和珊瑚红表达操作与状态。最终观感应接近现代竞技设备界面，而不是黑底霓虹灯、儿童糖果色或传统企业后台。

### 视觉原则

1. 大面积区域承担明度，小面积高光承担赛博感。
2. 信息层级主要依靠明度、留白和排版建立，不依赖每个元素都加荧光边框。
3. 同一功能区采用一致的容器规则：该有框的同级模块全部有框，装饰框不混入内容层级。
4. 主要内容占据更大的有效窗口面积，避免居中小卡片造成“小气”观感。
5. 游戏状态必须先于装饰效果被识别，任何纹理和高光都不得降低读数与格子辨识度。

## 视觉系统

### 色彩语义

- 页面背景：明亮深海蓝灰，不使用接近纯黑的底色。
- 背景网格：仅比背景略亮，低密度、低对比，不穿透主要面板争夺注意力。
- 主表面：银蓝深色；次表面：冰蓝灰；悬停表面：提高明度而非单纯提高饱和度。
- 主操作：清亮青蓝，深色文字，保证按钮一眼可见。
- 成功：薄荷绿；提醒：太阳黄；危险与旗帜：珊瑚红；辅助强调：克制的电光紫。
- 主文字：近白冷灰；次文字：蓝灰；禁用文字仍需可读，不降到背景噪声级别。

颜色集中定义在 `ui_theme.py` 的语义 token 中。页面不得自行散落硬编码主题色，棋盘数字色和危险态除外，但也应由共享 token 提供。

### 排版与尺度

- 中文使用 Microsoft YaHei UI，数据、时间和状态使用 Consolas。
- 页面标题清晰但克制，避免在紧凑功能面板中使用海报级字号。
- 窗口维持当前大尺寸策略，并增大有效内容宽度；登录页不再使用过窄的中心卡片。
- 统一 8、12、16、24、32 像素的间距节奏；同级按钮保持等高、等宽或占据相同网格轨道。

### 容器与边框

- 顶级功能区使用一像素边界和轻微内高光，边框颜色随层级变化。
- 同一组功能卡片采用同样的边框、内边距和标题结构。
- 主面板不嵌套装饰性卡片；确有独立语义的统计项可作为重复模块。
- 聚焦和选中时才使用高亮边框，静态状态使用清晰但克制的银蓝边界。

## 页面设计

### 登录与注册

- 语言选择固定在页面左上角，是一个完整模块：标签与下拉框属于同一外框，内部保持清晰分区。
- 提供简体中文、繁體中文、文言文及现有全部主流语言；这是单语言选择，不是双语转换。
- 登录与创建新账号两个主要操作区域使用完全相同的宽度和高度。
- 主内容区域扩大，使用横向空间建立产品感，不展示仓库、GitHub、版本调试信息或其他隐私内容。
- 错误信息在表单内显示，避免无意义的系统弹窗；真正需要阻断的严重错误才使用对话框。

### 大厅

- 难度选择是页面中心，三个难度形成统一竞技入口，尺寸、边框和状态反馈一致。
- 玩家身份、联网状态、档案与排行榜属于辅助操作，清晰可见但不抢占主视觉。
- 删除重复说明和重复玩家信息；每条信息只保留一个权威展示位置。
- 使用更宽的内容轨道和更明显的标题层级，形成大气、开放的大厅感。

### 个人档案

- 个人概览、历史统计和操作区各自形成完整、有边框的功能区，不出现同一功能内“有的有框、有的没框”。
- 两个主要操作按钮扩大，并占据相同尺寸的网格轨道。
- 删除重复账号字段和重复战绩摘要，保留用户真正需要比较的数据。

### 排行榜

- 排名、玩家、时间和日期具有稳定列宽及明显表头。
- 前三名、当前玩家、空状态和云端故障使用不同但一致的语义状态。
- 云端与本地成绩合并逻辑保持不变；界面只显示游戏相关联网状态，不显示代码仓库信息。
- 个人最佳摘要与榜单使用相同容器语言，避免上下区域像两个不同产品。

### 游戏页与 HUD

- HUD 按“返回与模式、剩余雷数、时间、进度、密度、重开”组织，主次明确。
- 棋盘尽可能占据窗口主要面积，周围留白用于聚焦而非缩小棋盘。
- 结算作为游戏页内完整结果区出现，胜负、成绩、重开、返回大厅和排行榜按操作优先级排列，不弹出无意义窗口。

## 棋盘渐变与状态

### 未打开格

- 恢复最早版本左上到右下的连续渐变：`t = (row + col) / (rows + cols - 2)`，在两个端点色之间进行 RGB 插值。
- 不再使用完全随机 HSV 色。每局从经过审核的色组中选择，例如青蓝到薄荷绿、天蓝到电光紫、海蓝到青绿。
- 色组限制亮度与饱和度区间，确保健康明亮但不呈现糖果感。
- 格子紧密连续，不通过粗间隙分隔；使用一像素边缘、内高光和悬停轮廓标示坐标边界。

### 已打开格

- 已打开格完全退出彩色渐变，使用统一的低彩度浅钢蓝或冷灰扫描面。
- 已打开区域在视觉上连成一片，但通过非常轻的内边缘保留单格定位能力。
- 未打开格与已打开格必须同时存在明显的明度差、饱和度差和表面质感差，不能只改变一个近似色值。

### 数字、旗帜与危险态

- 1 至 8 的数字颜色逐级区分，并在已打开底色上保持清晰对比。
- 旗帜使用珊瑚红主状态，可保留少量当前位置渐变痕迹，但危险语义必须优先。
- 爆雷格、错误旗帜、悬停、按下和和弦操作分别拥有明确反馈。
- `9x9` 强调材质细节；`27x27` 平衡细节与密度；`81x81` 优先保证缩放、滚动与数字识别，不强行保留不可见的装饰线。

## 架构与实现边界

- `ui_theme.py` 负责颜色、字体、尺寸、共享按钮、输入框、面板、标题和背景。
- `game.py` 负责棋盘色组选择、位置插值、状态绘制与各尺寸渲染。
- `auth.py`、`main.py`、`ranking.py` 只组合共享视觉构件并表达各页面信息层级。
- `lang.py` 只维护界面文案和语言选项，不把样式逻辑混入翻译资源。
- 保留现有未提交优化，不回滚账号、语言、布局、排行榜和棋盘相关改动；在其上重构。
- 不删除、迁移或重建 `%LOCALAPPDATA%\CyberMinesweeper\minesweeper.db`。

## 错误与联网状态

- 登录失败、注册校验、网络不可用等可恢复问题使用页面内状态信息。
- 云排行榜不可用时继续展示本地成绩，并明确标注当前数据来源或同步失败。
- 后台联网不得阻塞 Tk 主线程；窗口销毁后应取消轮询任务。
- 视觉重构不得改变注册、登录、成绩写入和云榜合并的数据行为。

## 验收标准

### 视觉验收

- 实际截取并检查登录、注册、大厅、个人档案、排行榜、游戏和结算界面。
- 检查常规桌面窗口与最小尺寸，确保文字、按钮、下拉框和功能区不重叠、不截断。
- 分别检查 `9x9`、`27x27`、`81x81` 棋盘。
- 固定生成同时包含未打开、已打开、数字、旗帜和雷的棋盘状态，确认无需仔细辨认即可区分状态。
- 棋盘仍表现为连续整体，格子边界清楚但没有粗黑缝。
- 全项目只显示“扫雷”作为产品名，不出现“赛博扫雷”或仓库隐私信息。

### 自动验证

- 为渐变插值、色组范围、已打开/未打开感知差异和关键布局约束补充测试。
- 运行全部单元测试和 Python 编译检查。
- 运行 `git diff --check`，确保没有空白错误。
- 使用发布脚本重新生成根目录 `扫雷.exe`，完成启动冒烟检查并核对生成时间与文件大小。

## 非目标

- 不重写扫雷规则引擎。
- 不更换账号体系、数据库结构或云排行榜服务。
- 不增加仓库浏览、开发者面板或 GitHub 展示。
- 不为了视觉效果引入与 Tkinter 不兼容的重型前端框架。
