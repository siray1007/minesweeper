# 扫雷重构设计

## 目标

把当前偏儿童化、视觉杂乱、编码破损的扫雷项目，重构成一款深色、硬朗、带赛博朋克气质的桌面游戏客户端。

核心目标：
- 视觉从“彩色玩具”切换为“黑底霓虹竞技客户端”
- 保留扫雷核心玩法、登录、排行榜、语言切换和本地存档
- 修复乱码文案、资源命名混乱和 UI 结构耦合
- 让代码结构更清晰，后续改主题、改布局、改规则都更容易

## 非目标

- 不更换技术栈，仍然使用 Tkinter
- 不把项目改成网页或 3D 游戏
- 不新增复杂社交、商城、任务系统
- 不重写扫雷规则，只做界面与结构升级

## 设计原则

- 视觉先统一，再谈细节
- 核心规则保持稳定，UI 和逻辑解耦
- 每个模块只做一件事
- 文案、颜色、资源名全部可维护
- 默认深色，强调色少而准，不用糖果感配色

## 最终体验

启动后用户看到的不是“游戏菜单”，而是一个赛博风的桌面客户端。

### 登录区

- 深色背景，金属边框，冷色高亮
- 用户名和密码输入框更紧凑，减少空白
- 切换语言入口保留，但改成更像系统设置的小菜单
- 登录/注册按钮更像控制面板按钮，而不是卡通按钮

### 大厅

- 顶部状态栏显示用户名、模式、排行入口、退出入口
- 中央是三种难度卡片，但卡片更像竞技模式面板
- 卡片使用不同霓虹强调色区分难度
- 增加轻微扫描线、发光边框、金属分隔线等赛博元素

### 对局页

- 顶部信息条固定显示剩余雷数、计时、难度名称
- 棋盘保持清晰可读，但视觉语言更硬朗
- 未翻开格子使用深浅分层而不是彩虹渐变
- 标记、数字、爆雷状态统一配色
- 大棋盘保留缩放和滚动，但控件样式统一

### 排行页

- 排行榜做成“战绩面板”
- 本地和云端数据分层展示，当前用户高亮
- 日期、耗时、难度信息对齐，便于扫读

## 信息架构

应用保持四个主要视图：

1. 登录 / 注册
2. 主大厅
3. 对局
4. 排行榜

设置项不单独开复杂页面，先收敛到语言与主题相关入口，避免范围膨胀。

## 模块拆分

### `game.py`

只保留扫雷规则与对局视图。

拆分为两个层次：
- `MinesweeperGame`：纯规则，负责生成雷、翻开、插旗、连点、胜负判断
- `GameFrame`：Tk 视图，负责渲染棋盘、状态条、缩放、输入事件、胜负弹窗

要求：
- 规则层不依赖 Tk
- 视图层不直接操作数据库
- 视图层只通过规则对象拿状态

### `main.py`

只负责应用壳和页面切换。

职责：
- 初始化 Tk
- 设置窗口标题、尺寸、图标
- 切换登录、大厅、对局、排行榜
- 处理全局退出和返回逻辑

### `auth.py`

只负责登录和注册界面。

要求：
- 表单布局更紧凑
- 语言切换保留
- 所有文案来自统一语言资源

### `ranking.py`

只负责排行榜视图。

要求：
- 本地和云端数据合并逻辑清晰
- 当前用户高亮
- 空状态和加载状态明确

### `ui_theme.py`

收敛为主题和通用控件工具。

包含：
- 颜色 token
- 字体 token
- ttk 主题配置
- 输入框样式
- 图标加载
- 窗口几何工具

### `lang.py`

修复并重建语言资源。

要求：
- 删除乱码文本
- 每种语言都至少保证主流程可用
- 所有文本 key 保持稳定
- 资源读写保持 UTF-8

### `database.py`

保留本地 SQLite 和云端排行榜逻辑，但清理注释、命名和错误处理。

要求：
- 本地登录注册稳定
- 排行榜写入与读取不影响离线玩
- 云端失败时静默降级，不阻塞对局

## 视觉系统

### 调性

- 深色为主
- 冷色霓虹点缀
- 少量红色用于危险与操作强调
- 不使用大面积紫色渐变，不做糖果化配色

### 组件风格

- 面板：直角或小圆角，偏硬朗
- 按钮：扁平、紧凑、带轻微 hover 发光
- 输入框：暗底、细边框、焦点高亮
- 卡片：更像控制台模块，不像软糯卡片
- 棋盘：清晰优先，效果服务可读性

### 图形元素

- 可使用细线、网格、扫描条、微弱故障感
- 可以保留少量 bomb 图标，但不做表情化处理
- 禁止大面积装饰性圆点和软萌图案

## 数据流

1. 用户登录后，`main.py` 保存当前用户信息
2. 进入大厅，选择难度后创建 `GameFrame`
3. `GameFrame` 持有 `MinesweeperGame`
4. 对局结束后，视图层调用 `database.py` 保存战绩
5. 排行页从本地和云端读数据并合并展示

这个流里，规则层不认识 UI，UI 不直接拼 SQL，排行榜页不修改规则状态。

## 迁移顺序

1. 先修复编码和语言资源
2. 再重做主题 token 和基础控件样式
3. 然后改登录页、大厅、排行榜的版式
4. 最后重构对局页的棋盘视觉和状态区
5. 补测试并清理残留的旧文案、旧图标引用

## 错误处理

- 登录失败、注册失败、云端排行失败都要有明确反馈
- 云端请求超时后直接使用本地数据
- 图标或主题资源缺失时必须有安全降级
- 棋盘点击越界、重复点击、已结束对局等情况保持静默或轻提示

## 测试策略

### 规则测试

- 未知难度应抛错
- 首次点击必须避开安全区
- 插旗会影响剩余雷数
- 命中雷会结束游戏
- 清空安全格会胜利

### 界面测试

- 登录页按钮必须在卡片内部
- 大厅布局在默认窗口尺寸下不溢出
- 排行页空状态不空白

### 回归测试

- 语言切换后主流程按钮仍可点击
- 赛事记录保存后排行榜能读到
- 大棋盘缩放后点击坐标仍正确

## 风险

- 语言资源历史包袱太重，修复时容易漏 key
- 赛博风容易做过头，必须控制霓虹使用密度
- Tkinter 对复杂视觉效果支持有限，所以要靠布局、配色、层级取胜，而不是堆特效
- 大棋盘性能要保持，不能因为视觉升级导致滚动卡顿

## 完成标准

- 打开应用后，视觉上明显不像原来的儿童化版本
- 文字无乱码，资源加载正常
- 登录、开局、翻雷、插旗、排行榜流程都可用
- 核心规则测试通过
- 页面结构清楚，后续改主题不需要再大拆
